# S-5 — `uvx` start, workspace materialization, lifespan + background watcher (task F0-05)

> Status: done 2026-10-31 (Linux only) · Informs: DD-011, DD-016, DD-017, R-5, REQ-UI-001, REQ-NFR-003, REQ-NFR-011
> Spike code: `spikes/S-5/` (throwaway, not merged)

## Question

1. Can a Reflex 0.10 app shipped as package data inside a wheel be started with
   `uvx --from <wheel> <cli> run`, materialized into
   `platformdirs.user_cache_dir(...)/app/<version>/`, bound to `127.0.0.1`? What is the
   right Reflex 0.10 invocation (env mode, ports, host)?
2. Cold and warm start times until the page is served and interactive (target: warm < 10 s).
3. Does anything get written under the uvx environment's site-packages?
4. (R-5 / DD-011) Does a lifespan task that publishes to an anyio memory object stream, consumed
   by a per-tab `@rx.event(background=True)` watcher applying updates inside `async with self`,
   work with two tabs, and does the watcher end when its tab closes?
5. (DD-017) Can `rx.App(api_transformer=...)` install a Host/Origin guard covering HTTP and the
   event websocket? What happens when the UI is reached via `localhost` instead of `127.0.0.1`?

## What was tried

Package `spikes/S-5/` (`s5-probe` 0.0.1, hatchling, src layout):

- `src/s5_probe/web/` holds `rxconfig.py` and `s5app/s5app.py`, shipped in the wheel as package
  data (verified with `unzip -l`).
- `s5-probe run` (`src/s5_probe/cli.py`) copies `rxconfig.py` + `s5app/` to
  `platformdirs.user_cache_dir("s5-probe")/app/<version>/` when the marker file is missing or its
  content hash differs, then runs, with that directory as cwd:
  `sys.executable -m reflex run --env prod --backend-host 127.0.0.1 --frontend-port P --backend-port P`
  with `GRANIAN_WORKERS=1`, `REFLEX_CHECK_LATEST_VERSION=false`. `rxconfig.py` sets
  `telemetry_enabled=False`, `api_url = deploy_url = http://127.0.0.1:P`,
  `cors_allowed_origins=["http://127.0.0.1:P"]`. It never opens a browser.
- The app has a lifespan coroutine (`app.register_lifespan_task(publisher)`) that publishes a tick
  every 0.5 s to a fan-out bus (one `anyio.create_memory_object_stream(16)` per subscriber,
  `send_nowait`, drop on full). The `S5State.watch` background handler subscribes, then for each
  item does `async with self: self.ticks += 1`. `S5_START=load|mount` selects `on_load` (page) or
  `on_mount` (component) as the trigger. A `/s5/debug` Starlette route (mounted through
  `api_transformer`) reports live watchers and bus subscribers.
- `S5_GUARD=1` appends a pure-ASGI guard to `api_transformer`. It returns 403 when `Host` is not
  `127.0.0.1:P` or when `Origin` is present and is not `http://127.0.0.1:P`. For websockets it sends
  `websocket.close` before accept, and granian answers HTTP 403.
- `measure.py` starts `uvx --from dist/s5_probe-0.0.1-py3-none-any.whl s5-probe run`. It times
  (a) the first `GET /` → 200 and (b) Playwright `#ticks > 0`, meaning the websocket is up, state
  is hydrated, and lifespan → bus → watcher → UI works end to end. The browser is launched before

- `snapshot.py` records (path, mtime, size) for the uvx env's purelib before and after runs.
- `tabs.py` (two browser contexts, close one, reload the other) and `guard.py` (HTTP/WS header
  matrix plus a browser via `127.0.0.1` and via `localhost`).
- Also tried `--env dev` once, to see how it binds.

## Answer

### 1. Invocation (Reflex 0.10.1)

- **`--env prod` forces a single port.** `_run` rejects
  `frontend_port != backend_port` in prod/preview ("In prod mode, frontend and backend must run on
  the same port"). The backend (granian) serves the compiled frontend itself
  (`REFLEX_MOUNT_FRONTEND_COMPILED_APP`, `exec.get_frontend_mount`). The two-port layout that
  DD-016/DD-017 assume does not exist in prod.
- `--backend-host 127.0.0.1` binds the single listener to `127.0.0.1:P` only (`ss -ltn`). The
  `backend_host` default is `0.0.0.0`.
- **`--env dev` is unsafe for us.** The Vite dev server listened on `*:P+1` (all interfaces, IPv4
  and IPv6), ignoring `--backend-host`. Only the backend was on `127.0.0.1`.
- In prod, the number of workers is 1 unless Redis is configured (`processes.get_num_workers`);
  `GRANIAN_WORKERS` overrides it. Pinning `GRANIAN_WORKERS=1` keeps "one Host per backend process"
  equal to "one Host".
- `config.api_url` defaults to `http://localhost:<backend_port>`. The frontend (`state.js`
  `getBackendURL`) rewrites `localhost`/`0.0.0.0`/`::` to `window.location.hostname`. With
  `api_url` set to `http://127.0.0.1:P`, the generated `env.json` points every endpoint
  (`/_event`, `/ping`, `/_upload`, …) at `127.0.0.1:P`.
- First run inside the workspace also writes Reflex init files there: `.web/`, `.states/`,
  `reflex.lock`, `requirements.txt`, `.gitignore`, `__pycache__/`. Bun (≈103 MB) goes to
  `REFLEX_DIR` (default `~/.local/share/reflex`) and the npm cache (≈175 MB) to Bun's cache
  (default `~/.bun/install/cache`). Both are user-global and outside site-packages and the workspace.

### 2. Timings (Linux; macOS and Windows not measured)

"Interactive" = Playwright sees `#ticks > 0` (socket connected, hydrated, first background update rendered).

| Run | HTTP 200 (s) | Interactive (s) | Notes |
|---|---|---|---|
| cold-full-1 | 68.4 | **68.9** | everything fresh, including uv download/install of 42 packages |
| cold-reflex-2 | 62.5 | **62.9** | uvx env pre-created (14.1 s, not included); breakdown: Bun download ≈12.5 s, web-dir init ≈2 s, frontend `bun install` + Vite build ≈46.7 s |
| cold-reflex-3 | 69.7 | **70.1** | uvx env pre-created with `--compile-bytecode` (4.4 s, not included); Bun ≈10.3 s, init ≈3.9 s, install + build ≈54.8 s |
| warm-1 … warm-6 | 2.08–2.46 | **2.55–2.89** | trivial page, same version, same workspace |
| warm-7 … warm-9 | 2.45–2.90 | **2.88–3.29** | after the wheel was rebuilt (final code) |
| warm-guard-1 | 3.35 | 3.81 | with the DD-017 guard on |

Warm < 10 s: **met** on Linux, with a margin of about 5–7 s. **Surprise:** `_run_prod` always calls
`build.setup_frontend_prod` → `build()`, so every prod start re-runs the Vite production build:
≈1.6 s for the trivial page, ≈3–4 s for the heavier page. The warm cost grows with UI size. A start
that adds new JS dependencies (the first run of a new version) costs about 11 s even with warm caches.

### 3. site-packages

- **No app or build artifacts** (`.web`, `.states`, `rxconfig`, compiled JS) are ever written under
  the uvx env. Warm runs: 0 added, 0 changed, 0 removed entries (2697 entries compared).
- **However**, on the first run CPython wrote **641 `__pycache__/*.pyc`** files (77 directories'
  mtimes changed) under site-packages, including `s5_probe/__pycache__`. uv does not compile
  bytecode by default. With the env created by `uvx --compile-bytecode` (or
  `UV_COMPILE_BYTECODE=1`), the cold run made **0 changes** (3587 entries compared).
  `PYTHONDONTWRITEBYTECODE` in the Reflex child would not cover the uvx entry process itself.

### 4. Lifespan task + background watcher (R-5)

- `app.register_lifespan_task(coro_fn)` runs the coroutine as an asyncio task inside the backend's
  Starlette lifespan. It is cancelled on shutdown (`task.cancel(msg="lifespan_cleanup")`, 5 s wait),
  and our `CancelledError` handler ran on SIGINT. anyio memory streams shared between the lifespan
  task and background handlers worked: same event loop, no errors.
- **Two tabs:** both watchers received every item. Tab A went 2→6 and tab B 1→5 over 2 s, with 2 bus
  subscribers.
- **Tab close with `on_load` start:** the watcher was cancelled (`CancelledError`) in under 0.5 s.
  Bus subscribers dropped 2→1 and tab A kept updating. On a reload, the old watcher was cancelled
  and a new one started for the **same token**. State persisted (the counter continued at 26).
- **Tab close with `on_mount` start: NOT cancelled.** Both watchers stayed alive after their tabs
  and the whole browser closed, still consuming the bus and running `async with self` on orphaned
  state, until the backend shut down. Source: `BaseStateEventProcessor._on_disconnect` only cancels
  pending hydrations and the unfinished **`on_load_internal` chain** of the token.
  `EventProcessor._on_disconnect` says "without cancelling independent event work". So DD-011's
  "Reflex cancels them" holds only for watchers chained from a page `on_load`. Per the same source
  (`_supersede_previous`; not tested with several routes), a (re)connect or navigation that enqueues
  a new page load also cancels the previous `on_load` chain.
- Prototype pitfall: a "watching" flag kept in Reflex state survives a reload (same token) while the
  task is cancelled. That blocked the restart. De-duplication must be process-local (a dict keyed by
  token), and the code must tolerate cancellation without touching state.
- A fallback probe of the private `app.event_namespace._token_manager.token_to_socket` did detect
  disconnects for `on_mount` watchers. It is private API and not recommended.

### 5. Loopback guard (DD-017)

- `rx.App(api_transformer=callable | Starlette | Sequence[...])` is public and documented (v0.10
  docs "API Transformer"). In `App.__call__` it wraps `self._api`, and that includes the socket.io
  `/_event` mount and, in prod, the compiled-frontend static mount. Reflex's `_ContextMiddleware`,
  CORS and lifespan sit outside it, in `top_asgi_app`. One middleware therefore covers HTTP, the
  websocket and the static UI.

| Request (single port P) | No guard | Guard on |
|---|---|---|
| `GET /` Host=127.0.0.1:P | 200 | 200 |
| `GET /` Host=localhost:P | 200 | **403** |
| `GET /` Host=evil.example:P (rebinding) | 200 | **403** |
| `GET /ping` Origin=http://evil.example | 200 | **403** |
| `GET /ping` Origin=http://localhost:P | 200 | **403** |
| WS `/_event` Origin=http://127.0.0.1:P | open | open |
| WS no Origin | open | open |
| WS Origin=http://evil.example | 403 (socket.io CORS) | 403 |
| WS Origin=http://localhost:P | 403 (socket.io CORS) | 403 |
| WS Host=evil.example, Origin ok | **open** | **403** |
| Browser via `http://127.0.0.1:P` | interactive | interactive |
| Browser via `http://localhost:P` | page loads, not interactive | **403**, empty page |

- Without the guard, socket.io's `cors_allowed_origins` already rejects foreign websocket Origins,
  but it does not check Host and does not protect plain HTTP. The guard is still needed.
- `localhost` reached the server even though it listens only on `127.0.0.1`: the resolver falls
  back to IPv4. With the guard on, the static UI is itself refused. The planned frontend notice
  ("open http://127.0.0.1:<port>", shown when `location.hostname !== '127.0.0.1'`) **can never be
  rendered** in prod single-port mode. The notice must be the guard's 403 HTML body.

## Impact

- **DD-016 confirmed in substance** (wheel-shipped sources, cache-dir workspace, `.web` outside
  site-packages, warm < 10 s on Linux), with corrections:
  - Run Reflex as `reflex run --env prod --backend-host 127.0.0.1 --frontend-port P --backend-port P`
    with **one** port. There are no separate frontend and backend ports, and `--env dev` must not be
    used (Vite binds all interfaces).
  - Set `GRANIAN_WORKERS=1` and `REFLEX_CHECK_LATEST_VERSION=false`, set `telemetry_enabled=False`
    and an explicit loopback `api_url`/`deploy_url` in the packaged `rxconfig.py`.
  - The "no writes to site-packages" criterion must either exclude CPython bytecode caches or
    require `uvx --compile-bytecode` / `UV_COMPILE_BYTECODE=1` in the documented start command.
    Recommendation: document `uvx --compile-bytecode reflex-mcphost run` and define the criterion as
    "no files other than `__pycache__/*.pyc`".
  - Key the workspace on version **plus a content hash** of the packaged sources. Version-only
    reuses a stale workspace for `.devN` rebuilds with the same version.
  - Note in REQ-NFR-003 / the plan that each warm start includes a Vite production build (it grows
    with UI size), and that the first start of a new version may exceed 10 s when JS deps change.
    Phase 6 should re-measure warm start with the real UI (risk flag, not a blocker).
- **DD-011 confirmed with one required change:** the per-tab watcher must be started from the page
  **`on_load`** (on every page that needs it), not "on mount". Only `on_load` chains are cancelled on
  disconnect, and they are restarted on reconnect or reload. De-duplicate watchers per token in a
  process-local registry, not in Reflex state. A lifespan task feeding anyio memory streams works,
  so R-5 is retired for the single-worker case.
- **DD-017 confirmed (mechanism) with changes:** `api_transformer` covers HTTP, the `/_event` websocket
  and the static UI. The allowed values become `Host == 127.0.0.1:<port>` and
  `Origin ∈ {absent, http://127.0.0.1:<port>}` for the **single** port. The "open 127.0.0.1" notice
  moves from a frontend script into the guard's 403 response body. Keep `cors_allowed_origins`
  restricted to the same origin as defence in depth.
- **Delta Spec required: yes** (small, no REQ weakened). It should cover DD-011 (`on_load` trigger,
  process-local de-dup), DD-016 (single port, prod only, workers=1, bytecode wording, content-hash
  key, build-per-start note), and DD-017 (single port, 403 body as notice). It should also check
  F6-08's CLI flags (`--port` instead of separate frontend/backend ports) and F7-06 (the E2E via
  `localhost` should expect 403 plus the notice text).
- macOS and Windows timings and the site-packages check remain **open** (CI matrix in Phase 6/7).

## Contract assertions

For the Reflex surface test (F1-11):

1. `inspect.signature(rx.App.register_lifespan_task)` is `(self, task=None, **task_kwargs)`. A
   coroutine function is run as a task and cancelled on shutdown; a parameter named `app` receives
   the `rx.App`. Registering after lifespan start raises `RuntimeError`.
2. `rx.App` accepts `api_transformer` as a callable `ASGIApp -> ASGIApp`, a `Starlette` instance,
   or a sequence of them, applied in order. An HTTP request to `/ping` and a websocket to `/_event`
   both pass through the transformer (pin with an ASGI test client: a transformer that records
   `scope["type"]`/`path` sees `http` and `websocket`).
3. `reflex run` accepts `--env {dev,preview,prod}`, `--frontend-port`, `--backend-port`,
   `--backend-host`, `--single-port`. In prod, different frontend/backend ports exit with code 1
   (pin via `reflex.reflex._run` or a CLI subprocess with `--help` + a quick invalid call).
4. `reflex_base.config.Config` has `api_url`, `deploy_url`, `backend_host` (default `"0.0.0.0"`),
   `cors_allowed_origins`, `telemetry_enabled`. The default `api_url` uses `localhost`, so our
   `rxconfig.py` must set it explicitly.
5. `reflex.utils.processes.get_num_workers()` returns 1 when no Redis is configured, and the
   `GRANIAN_WORKERS` environment variable is honoured by `run_granian_backend_prod`.
6. `@rx.event(background=True)` handlers chained from a page `on_load` are cancelled when the
   client disconnects. Handlers started from `on_mount` are not. Pin through
   `BaseStateEventProcessor._on_disconnect` cancelling only hydration and the `on_load_internal`
   chain (or an E2E test in F7). If this changes, DD-011's trigger can be revisited.
7. `reflex_base.environment.EnvironmentVariables` exposes `REFLEX_DIR`, `REFLEX_WEB_WORKDIR`,
   `REFLEX_CHECK_LATEST_VERSION`, `REFLEX_MOUNT_FRONTEND_COMPILED_APP`. The Bun version constant is
   `reflex_base.constants.installer.Bun.VERSION == "1.4.4"` (informational: a change means
   re-measuring cold start).
8. The generated `.web/env.json` `EVENT` URL equals `ws://127.0.0.1:<port>/_event` when
   `api_url = "http://127.0.0.1:<port>"`.
